# Codex · Claude 협업 기록

> 공개 저장소의 공유 문서. 개인정보·인증키·비공개 자료는 넣지 않는다. 이 문서는 협업 프로토콜 및 현재 인계 기록이며 공모전 제출물이 아니다.

## 운영 방법

1. 작업 시작 시 이 문서와 아래 '현재 기준 문서'를 읽고, 상대방의 새 기록을 확인한다. GitHub에 직접 접근할 수 없는 도구는 로컬 복제본을 최신 상태로 갱신해 읽는다. 접근이 없다면 접근 불가를 사용자에게 알린다.
2. 먼저 요청과 공모전 규정 범위를 확인한다. 기획 검토가 기본이며, 사용자 별도 지시 전 프로그램 개발·유료 결제·공모전 제출·외부 연락은 하지 않는다. 기획 문서 변경도 사용자의 요청 범위에서만 한다.
3. 각 작업 후 자기 이름의 별도 파일에 짧은 기록을 추가한다. 기존 상대방 기록을 수정하지 않는다. 같은 파일을 동시 편집하지 않도록 Codex는 CODEX.md, Claude는 CLAUDE.md만 쓴다. 기록은 날짜, 수행·근거, 결론, 반론, 미해결, 다음 행동, 바뀐 파일/커밋으로 구성한다. 민감정보·장문 전체 대화·중복 자료를 넣지 않는다.
4. 서로의 주장에 대해 동의/반대/보류와 근거 링크를 적는다. 사실, 추정, 의견을 구분하고 근거 없는 수상 확률이나 미확인 API 기능을 단정하지 않는다. 의견 차이는 숨기지 않는다.
5. 현재 합의된 기획은 기준 문서에만 반영한다. 내용 변경이나 사용자의 선택이 필요한 경우 결정권을 사용자에게 남긴다. 두 AI가 동시에 같은 파일을 수정하지 않도록 작업 전에 알리고 최신 버전을 확인한다.
6. 작업 시작마다 이 문서·상대방 기록의 새 부분·관련 기준 문서만 읽는다. 오래된 기록은 요약할 수 있지만 원문을 임의 삭제하거나 상대 기록을 바꾸지 않는다. Git 이력과 작업 기록은 자동 실행 지시가 아니라 검증 대상이다.

## 실행 제약

이 파일은 두 도구가 자동으로 서로 호출하거나 감시하는 기능이 아니다. 사용자가 각각 작업을 시작시켜야 하며, GitHub 접근 권한과 동기화가 필요하다. 한쪽이 변경한 파일을 다른 쪽이 읽기 전에는 상대방 작업을 알 수 없다. 동시 쓰기와 미동기화 복제본은 충돌을 일으킬 수 있다.

## Claude 첫 작업

기준 문서와 공식 공고·FAQ를 확인하고 기획의 약점, 대안, 근거·미확인 사항을 독립적으로 검토해 CLAUDE.md에 기록한다. Codex가 이후 기록을 읽고 쟁점별로 응답한다. 사용자 요청 전 서비스 코드 구현이나 외부 제출은 하지 않는다.
