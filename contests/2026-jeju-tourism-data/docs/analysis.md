# 공고 분석과 응모 전략 (초안)

작성 2026-10-16. 사실과 해석을 구분한다. 근거는 [제출 규칙 요약](submission-rules.md).

## 1. 이 공모전은 무엇인가 (사실)

- **“분석 아이디어”가 아니라 “데이터를 실제로 활용해 성과를 낸 사례”**를 찾는다. 공지 문구: 분석으로 발견한 **주요 인사이트 → 실제 활용 내용과 성과 → 향후 발전 가능성**.
- 플랫폼 데이터 사용이 **필수**다. 플랫폼에는 입도통계, 이동통신, 내비게이션, 신용카드 소비 자료가 쌓여 있다(보도).
- 평가 키워드는 **활용 목적의 구체성 · 활용 과정의 충실성 · 데이터 활용도 · 결과와 성과**(공지·보도의 표현이 조금씩 다르다. 배점은 미확인).

## 3. 우리에게 맞는가 (해석)

- **맞는 점:** 사례 안에 “인사이트 → 활용 → 성과 → 확장성” 구조가 허용되고, 분석으로 얻은 발견도 사례의 일부로 인정하는 문구가 있다. 데이터 분석·시각화·LLM 활용 경험이 이 구조와 잘 맞는다.
- **위험 1 — 성과의 진정성:** “성과”는 실제로 일어난 것만 쓴다. 가짜 성과·가정한 수치를 성과로 쓰면 안 된다(서약·결격 위험). 실제 사업체·기관 적용이 없다면 **“분석으로 얻은 검증 가능한 인사이트 + 의사결정에 쓰이는 방식 + 후속 계획”**으로 정직하게 쓰고, 성과가 아닌 것은 ‘기대’로 구분 표기한다.
- **위험 2 — 자격:** 플랫폼 **이용자**여야 한다. 회원가입은 본인이 직접 해야 한다.
- **위험 3 — 시간:** 마감까지 15일, 같은 시기에 KOREAZ 공모전(10/25) 마감이 있다. 일정 충돌을 [일정표](schedule.md)에 반영했다.
- **위험 4 — 평가 기준 불명:** 배점과 분량을 모른다. 공고문 PDF 확인이 우선이다.

## 4. 응모 전략 (제안)

1. **주제는 ‘한 문장 질문’으로 좁힌다.** 예: “누구의 어떤 결정을 데이터로 바꿨는가.” 넓은 관광 트렌드 리포트는 약하다.
2. **플랫폼 데이터를 중심에 두고** 필요할 때만 외부 공공데이터(기상·행사·인구 등)를 얹는다. 활용 데이터가 어떤 항목·기간·단위인지를 사례 안에 명확히 쓴다(‘데이터 활용도’ 대응).
3. **“활용 과정의 충실성”**: 문제 정의 → 데이터 선택 이유 → 전처리·분석 방법 → 결과 → 해석의 한계까지 재현 가능한 기록으로 남긴다(`analysis/`에 노트북).
4. **“구체성·지속성”**: 누가 어떤 주기로 이 분석을 다시 쓸 수 있는지(대시보드·체크리스트 등)까지 제시한다.
5. 발표평가(11월 셋째~넷째 주)를 고려해 **발표 흐름이 처음부터 드러나는 사례 구조**로 쓴다.

## 5. 주제 후보 (가설 — 데이터 확인 전)

플랫폼에서 실제로 어떤 항목·기간·지역 단위가 열려 있는지 **확인한 뒤** 고른다. 아래는 공지의 환영 분야에 맞춘 가설일 뿐이다.

| 후보 | 질문 | 확인할 것 |
| --- | --- | --- |
| A. 상권·프로모션 타이밍 | 특정 권역에서 유동인구·카드소비가 오르는 시점을 사업체가 어떻게 쓸 수 있나 | 시간·지역 단위 해상도, 업종 구분 |
| B. 비수기·혼잡 분산 | 방문이 몰리는 곳과 비는 곳을 어떻게 나눠 안내·정책에 쓰나 | 이동통신·내비 데이터의 지역 단위 |
| C. 행사 성과 측정 | 행사 전후 방문·소비 변화를 어떻게 측정해 보고서로 쓰나 | 행사 일정 데이터, 비교군 설정 가능성 |

플랫폼에 올라온 기존 활용사례(예: “우리 가게 근처의 유동인구 급증을 확인하고 프로모션을 운영해보아요”)는 **기대되는 사례의 수준과 형식**을 보여주는 참고 자료다. 읽고 `assets/references/`에 메모한다.
